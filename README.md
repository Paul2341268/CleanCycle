# CleanCycle

React + FastAPI + SQLite로 만든 개인·가족·룸메이트 공동 집안일 관리 웹앱입니다.

## 다른 컴퓨터에서 실행 (Windows)

Python 3.11 이상과 Node.js 22 이상(npm 포함)을 먼저 설치합니다. Python은 launcher 또는 PATH 옵션을 활성화하고 설치 후 PowerShell을 다시 엽니다.

```powershell
git clone https://github.com/Paul2341268/CleanCycle.git
cd CleanCycle
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Git이 없으면 GitHub의 `Code → Download ZIP`을 눌러 압축을 풀고 해당 폴더에서 마지막 두 명령을 실행해도 됩니다. 설치 중 인터넷 연결이 필요합니다.

브라우저에서 http://127.0.0.1:8765 를 열고 회원가입 → 집 만들기를 진행합니다. 포트가 사용 중이면 `start.ps1 -Port 8767`로 실행합니다. 종료는 서버 PowerShell 창에서 `Ctrl+C`입니다. `setup.ps1` 재실행은 기존 API 키와 DB를 덮어쓰지 않습니다.

공공 API를 표시하려면 자동 생성된 `backend/.env`에 본인의 `KMA_SERVICE_KEY`, `AIRKOREA_SERVICE_KEY`를 입력합니다. 키 없이도 집안일·공동관리 기능은 실행되며 날씨·대기질은 연결 대기로 표시됩니다. 저장소에는 실제 키·계정·집안일 데이터가 들어 있지 않습니다.

GitHub는 소스코드 공유용이며 이 앱의 Python 서버를 GitHub Pages에서 실행할 수는 없습니다. 각 컴퓨터에서 서버를 실행하면 데이터는 각각의 `backend/cleancycle.sqlite3`에 저장됩니다. 서로 다른 기기에서 같은 집의 데이터를 공유하려면 같은 배포 서버 주소에 접속해야 합니다. 이 저장소는 2D 게임 포트폴리오와 독립된 프로젝트입니다.

## 사용

1. `backend/.env`의 `KMA_SERVICE_KEY=`와 `AIRKOREA_SERVICE_KEY=` 뒤에 각각 인증키를 같은 줄에 입력합니다. 키는 Git과 프론트엔드에 포함하지 않습니다.
2. 현재 PC에서는 `powershell -ExecutionPolicy Bypass -File .\start.ps1`로 실행합니다.
3. http://127.0.0.1:8765 를 엽니다. 서버가 실행 중이면 다시 실행할 필요가 없습니다.
4. 키 입력 후 화면의 날씨 새로고침을 누르면 됩니다. 재시작하지 않아도 설정을 읽습니다.
5. 회원가입 후 집을 만듭니다. `우리 집 설정`에서 초대 코드를 발급하면 다른 계정이 `초대로 참여`할 수 있습니다. 코드는 24시간 동안 유효하며 재발급·중지할 수 있습니다.
6. 집안일에 담당자를 지정하거나 미지정 작업의 `내가 맡기`를 누릅니다. 완료 기록에는 원래 담당자와 실제 완료자가 구분되어 남습니다.

기존 로그인 없는 버전의 기록이 있으면 서버가 DB 옆에 `legacy-claim-code.txt`를 만듭니다. 집 생성 화면의 `기존 개인 데이터 이전`에 해당 코드를 입력하면 한 번만 이전됩니다. 첫 가입자에게 임의로 이전하지 않습니다. 코드 파일과 DB는 비공개로 보관합니다.

## 새 개발 환경

Node.js 22 이상과 Python 3.11 이상을 사용합니다. `cleancycle` 폴더에서 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
cd frontend
npm ci
npm run build
cd ..
.\start.ps1
```

개발 중에는 백엔드를 실행한 상태로 `frontend`에서 `npm run dev`를 실행합니다. Vite가 `/api` 요청을 로컬 백엔드로 전달합니다.

## 구현 범위

- 반복 집안일 등록, 수정, 삭제, 공간별 필터
- 완료일 + 반복 주기로 다음 예정일 계산, 동일 날짜 중복 완료 방지
- 하루 미루기: 오늘과 기존 예정일 중 늦은 날의 다음 날
- SQLite 저장 및 최근 500건 완료 이력, 최근 7일 완료 건수
- 기상청 예보 연결 및 지역별 10분 메모리 캐시
- 예정일과 날씨에 따른 추천 순위 및 근거 표시
- 회원가입·로그인·로그아웃, HttpOnly 세션 쿠키와 비밀번호 scrypt 해시 저장
- 집별 데이터 분리, 초대 코드 참여, 관리자 이전·구성원 내보내기·집 나가기
- 담당자 지정, 내 담당·미지정 필터, 구성원별 최근 7일 완료 건수·비율
- 화면이 활성 상태일 때 15초 주기 및 포커스 복귀 시 공유 데이터 갱신
- revision 기반 동시 수정·완료 충돌 차단, 완료 취소는 실제 완료자 또는 관리자만 가능

실제 데이터가 없는 초기 화면은 비어 있습니다. 자주 하는 집안일을 눌러 추가할 수 있습니다. 카드의 반복 주기는 편집 가능한 초기값이며 공식 권장 주기가 아닙니다.

## 기상청 연결

출처: https://www.data.go.kr/data/15084084/openapi.do

`getVilageFcst`의 TMP, REH, POP, PTY를 사용합니다. 한국 시간의 발표 시각과 15분 여유를 고려하며, 현재 이후 가장 가까운 완전한 시간대의 예보를 선택합니다. 화면은 현재 관측값이 아닌 예보입니다. 지역은 7개 도시 대표 격자이며 정확한 집 주소의 날씨가 아닙니다.

실외 습도 75% 이상일 때 욕실 물기 관리 점수 +3, 비 예보 시 자연건조/야외 작업 -3, 예정일 지연 하루당 +2점의 데모 규칙을 사용합니다. 날짜는 자동 변경하지 않습니다. 실외 습도를 실내 습도로 간주하지 않으며 환기 안전 여부를 단정하지 않습니다.

## 에어코리아 연결

출처: https://www.data.go.kr/data/15073861/openapi.do

`getCtprvnRltmMesureDnsty`에서 선택 도시의 측정소 자료를 조회합니다. 지정 측정소를 우선 선택하며, 없으면 최신 자료를 가진 지역 내 측정소를 선택합니다. 측정소명과 시각을 표시하며 도시 평균이나 집에서 가장 가까운 측정소는 아닙니다. 원본 농도와 제공된 1시간 등급을 표시하고 결측/점검 자료는 0 대신 정보 없음으로 표시합니다. 3시간 넘게 지난 자료는 지연 표시하고 추천에서 제외합니다. 30분 캐시로 호출량을 줄입니다. 미세먼지 또는 초미세먼지 등급이 나쁨 이상이면 야외 청소 점수 -3을 적용합니다. 이 규칙은 앱의 자체 일정 추천입니다.

키가 없으면 연결 대기 상태, 통신/승인/응답 문제가 있으면 실패 상태를 표시합니다. 가짜 날씨는 표시하지 않습니다. API 오류 상세나 키가 포함된 URL을 로그/화면에 출력하지 않습니다. 공공 API 실제 승인 여부는 유효한 키 입력 후 확인해야 합니다.

## 쓰레기 배출 안내 범위

`우리 집 설정`에서 날씨 지역과 별도로 배출 지역을 저장합니다. 현재는 **서울 강남구 단독주택의 재활용품**, **부산 사상구 단독주택**, **인천 연수구 연수1·2·3동 단독주택**을 지원합니다. 전국 지원이나 구 전체의 모든 주택 유형 지원이 아닙니다. 공동주택 선택 시 단지별 기준 확인 안내만 표시하고 지역 기본 일정은 추천에서 제외합니다.

자료는 지자체 공식 공개안내를 수작업으로 정리한 스냅샷(확인일 2026-10-01)이며 **실시간 공공 API가 아닙니다**. 기상청·에어코리아 API와 구분합니다. 공식 출처 링크를 화면에 표시하며 명절·임시 수거 중단은 자동 반영하지 않습니다. 표시되지 않은 품목은 배출 금지가 아니라 미지원입니다. 연수동은 일반쓰레기와 달리 음식물·재활용품이 화·목·일 배출입니다.

작업 유형을 재활용품/음식물/일반쓰레기 배출 준비로 설정하면 해당 종류의 배출 시작일에 +3점을 적용합니다. 재활용품은 해당 날짜의 세부 품목을 추천 근거에 함께 표시합니다. 날짜나 반복 주기를 강제로 바꾸지 않으며 이 가산점은 공식 기준이 아닌 앱의 데모 추천 규칙입니다.

## 테스트 실행

```powershell
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest backend/tests -q
```

브라우저 테스트: `frontend`에서 `npx playwright test`. 테스트 서버가 8766 포트에서 자동 실행됩니다. Chrome이 필요합니다. 별도 임시 DB와 빈 API 키를 사용하므로 실제 사용자 기록을 바꾸지 않습니다.

새로 내려받은 저장소에서는 루트에서 `.\.venv\Scripts\python.exe -m pip install pytest` 후 `.\.venv\Scripts\python.exe -m pytest backend/tests -q`로 백엔드 테스트를 실행합니다. macOS/Linux는 `python3 -m venv .venv`, `.venv/bin/python -m pip install -r backend/requirements.txt`, `frontend`에서 `npm ci && npm run build`, `backend`에서 `../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8765` 순서로 실행합니다. 필요하면 `.env.example`을 `.env`로 복사해 키를 입력합니다.

## 데이터와 제약

한 계정은 한 집에 참여합니다. 관리자에게 구성원이 남아 있으면 권한 이전 후 나갈 수 있습니다. 마지막 구성원이 나가면 집은 보관 상태가 됩니다. 내보내거나 나간 사람의 담당 작업은 미지정으로 전환하고 완료 이력은 유지합니다. 자동 담당 배정은 하지 않습니다.

완료율은 오늘 완료한 작업 수 / (오늘 예정 작업과 오늘 완료 작업의 중복 없는 합계)입니다. 오늘 예정 작업은 미루기, 날짜 수정, 삭제 후에도 당일 분모에 남으며, 미룬 뒤 같은 날 완료하면 한 번만 계산됩니다. 업데이트 이전의 미루기 이력은 복원되지 않습니다. 완료 취소는 완료 후 작업 수정·미루기·추가 완료가 없는 기록만 가능합니다. 취소된 기록은 내부에 보관하고 완료 통계에서 제외합니다. 리포트는 최근 500건 완료 이력을 사용하므로 대량 운영 시 집계 API 확장이 필요합니다.

비밀번호 재설정, 이메일 인증, 푸시 알림, PWA 오프라인 설치는 아직 구현하지 않았습니다. 공개 서버를 생성하지 않았으며 현재 주소는 이 PC에서만 접근 가능합니다. 배포 구성과 인수 테스트는 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고합니다. SQLite를 유지하려면 단일 서버와 영구 저장공간이 필요합니다.

## 추가 기능

- 완료 목록과 리포트의 되돌리기 아이콘에서 완료 취소: 이전 예정일 복구와 통계 재계산, 변경된 작업은 충돌 방지.
- 작업의 추천 문구를 누르면 점수 반영 내역, 날씨·대기질 수치, 기준 시각, 출처를 확인합니다.
- 생활 리포트에 최근 7일 미룬 횟수, 상위 5개 작업, 날짜 변경 이력을 표시합니다. 신규 이력은 당시 제목과 공간도 보관합니다.
- 브라우저 테스트는 별도 DB와 빈 테스트 환경 설정으로 실행하며 실제 API 키를 사용하지 않습니다. 실제 연동 확인은 실행 중인 앱에서 별도로 수행합니다.
